# フェーズ2 動作確認手順

## テスト実行方法

### 1. ユニットテストでの確認（推奨）

Unityエディタで以下の手順を実行：

1. **Test Runner** を開く
   - `Window > General > Test Runner`

2. **EditMode** タブを選択

3. 以下のテストを実行：
   - `Phase2IntegrationTests`（統合テスト）
   - `CustomScreenSystemTests`（カスタム画面テスト）
   - `CardUsageSystemTests`（カード使用テスト）

4. すべてのテストが **緑（成功）** になることを確認

### 2. 実機動作確認

#### 方法A: Phase2VerificationScript を使う

1. 新しいシーンを作成または既存シーンを開く
2. 空のGameObjectを作成（`GameObject > Create Empty`）
3. 名前を「Phase2Verification」に変更
4. `Phase2VerificationScript` コンポーネントをアタッチ
5. **再生ボタン** を押す
6. **Console** ウィンドウでログを確認

**期待される出力:**
```
=== フェーズ2: カスタムシステム検証開始 ===
プレイヤー HP: 100/100
敵: 2体
デッキ: 6枚

--- 1. カスタムゲージのテスト ---

--- 2. カスタム画面を開く ---

  - ソード (コスト:3, 系統:ソード)
  - ワイドソード (コスト:4, 系統:ソード)
  - ロングソード (コスト:5, 系統:ソード)
  - ...

--- 3. カードを選択 ---

```

#### 方法B: 既存のBattlePrototypeController を使う

1. `Assets/Scenes/Phase1BattlePrototype.unity` を開く
2. **再生ボタン** を押す
3. **Cキー** を押してカスタム画面をテスト
4. Consoleログを確認

**操作方法:**
- `Z`: 1体目の敵に攻撃
- `X`: 2体目の敵に攻撃
- `C`: カスタム画面（ゲージ満タン時）
- `Space`: プレイヤーにダメージ（テスト用）

## 確認ポイント

### ✅ カスタムシステム
- [ ] カスタムゲージが満タンになる
- [ ] カスタム画面が開き、5枚ドローされる
- [ ] カード選択ができる
- [ ] 同名カードは1枚しか選択できない
- [ ] 系統ボーナス（同系統連続でコスト-1）が機能する
- [ ] コスト上限（10）を超えると選択できない
- [ ] 確定で画面が閉じる

### ✅ カード使用
- [ ] 選択したカードがキューに入る
- [ ] カードが選択順に使用される
- [ ] 攻撃カードでダメージが入る
- [ ] 回復カードでHPが回復する
- [ ] すべて使用後、キューが空になる

### ✅ バトルシステム統合
- [ ] カスタム画面中、バトルが一時停止する
- [ ] カスタム画面終了後、バトルが再開する
- [ ] ゲージがリセットされる
- [ ] イベントが正しく発火する

## トラブルシューティング

### テストが失敗する場合

1. **コンパイルエラー**
   - Unityエディタを再起動
   - `Assets > Reimport All` を実行

2. **NullReferenceException**
   - Assembly Definitionが正しく設定されているか確認
   - `Olca.Core.asmdef` が `Olca.Tests.asmdef` から参照できるか確認

3. **系統ボーナスが機能しない**
   - `CustomScreenSystem.cs` の `GetTotalUsedCost()` メソッドを確認
   - デバッグログを追加して、実際のコスト計算を確認

### 実機動作で問題がある場合

1. **Phase2VerificationScriptが動かない**
   - コンポーネントが正しくアタッチされているか確認
   - Consoleにエラーが出ていないか確認

2. **カードが使用されない**
   - `CardEffectFactory.CreateEffect()` が呼ばれているか確認
   - `BattleContext` が正しく生成されているか確認
