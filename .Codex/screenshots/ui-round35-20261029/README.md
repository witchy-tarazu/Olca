# 探索から接敵・初回カスタム／反復戦闘の監査（2026-10-29）

## 修正した問題

1戦目では上部パッド操作ガイドが濃色だったが、2戦目以降に白へ戻り、明るいパネル上で読みづらくなっていた。`CustomScreenView.Initialize`の一括白文字化がButton配下ではない既存guideにも適用される一方、生成済みguideには共通ラベル色を再適用していなかったことが原因。

既存guideへ`UiLook.Label`を再適用する2行（コメント含む）だけを製品側に追加した。本文の白文字・既存ボタン・表示状態・背景・JikiTourai・レイアウト・入力・固定フレーム・効果時間・報酬・保存形式は変更しない。

## 実操作の確認

隔離した専用保存先をController起動前に設定し、ガードを有効化。製品の敵配置や性能を変更せず、検証用マップで通常の自動探索→接敵→初回カスタムを通した。

- 仮想GamepadのSouth／DpadRight／Eastを接敵前から保持。ポーズを挟まない開始でも、初回と2戦目とも選択0枚・カーソル0・戦闘0論理フレーム・プレイヤーHP100・位置(1,0)。全体InputBlocked=false、手札アニメ完了時にも確認した。
- 入力を離した後の新しいSouthは1枚選択、Eastは1枚取消。初回確定後は論理フレームが進み、カスタムは閉じる。探索用ボタンは戦闘中に残らない。修正前の入力監査では、旧探索Jump／Dashボタンへ各3回pointer clickを送っても戦闘・選択は先行しなかった（製品側の入力コードは今回変更なし）。
- 1戦目の敵撃破は検証fixtureで成立させ、報酬skipと通常の探索再開から2戦目まで進行。接敵回数は2、Controllerの対象イベント購読は各1。旧CustomScreenのView購読9種は0、新モデルは各1。取得0・通貨0・終了台帳0を維持し、2戦目のFileCheckpointStoreと実状態はデッキ6／初手6／取得0で一致。
- 初回試行のpause中Eastは正規のメニュー取消として動作したため、接敵漏れの証拠とはしない。また、押し続け中の入力解放待ちで補助ボタンが無効だった待機ケースと、ポーズなしの接敵検証を区別した。期限超過した読み取り待ちは重複戦闘を起動せず状態確認して回収した。修正後の探索ボタン取得補助が早すぎた試行ではその追加チェックを未実施扱いとし、戦闘を再起動せず現在の保持入力・表示・反復戦闘の確認を続けた。

## 回帰とレビュー

既存の再初期化テスト2ケースに、Button外のguideの色・フォント・表示状態を追加。修正前は2件ともExpected濃色／Actual白で失敗し、修正後2/2成功。カスタム関連363/363成功、console error 0。

修正後の最終ソースでUnity 6000.3.26f1 MCP console→全EditMode→consoleを実施。640×360の統一条件で3462/3462成功（271.38秒、失敗／skip／inconclusive各0）、前後console error 0。前後のソースSHA256と提出コピーの一致を確認。高解像度の実画像検証とは実行条件を分離した。180秒の呼出側期限後も同じ実行を回収し、重複起動なし。変更前の全3462成功（266.28秒）とは別の実績。独立ソース再レビュー・最終6画像／資料／manifest確認は今回範囲で未解決指摘0。

## 範囲と限界

仮想padはUnity InputSystemの通常経路、pointerはEventSystem経路を使用。実機pad／物理キーボード／IME／OS通知は今回未確認。検証用撃破は攻撃性能の実機確認を意味しない。全入力組合せやゲーム全体の無欠陥保証ではない。未決の探索デッキ性能値・製品値を追加していない。

次候補は、探索中の訪問UI（既存ショップ等）から戻って接敵する際の入力所有とHUD切替。新機能を追加する候補ではない。
