隔離戦闘でプレイヤーを列0、通常敵と別敵ボスを列5へ配置し、実Viewの位置更新後にTakeDamage／Heal／Guard／Auraの既存経路から「7」「+7」「ガード」「ムコウ」を発生させた。修正前は各文字が画面内・同owner非重複でも、別敵の「ボス」へ重なった。修正後は文字群を横へ寄せ、別敵名も読むことができる。ゲームの通常移動操作そのものではなく、既存Controller戦闘に供給した検証用配置である。

自分の名前だけ／上端補正時だけの回避を、貸出時に参照した表示中の他敵TextMeshにも適用した。Renderer参照を一度集め、位置・enabled・active・forceRenderingOffは描画frameで再評価する。毎frameの全シーン検索は増やさず、強制非表示の名前を不要に避けない。

## 最終検証

- 関連17/17成功。追加1回帰は非上端で幅広Guardが別の敵名を回避し、同じ貸出中にラベル強制非表示→復帰→非表示で原点／回避が追従することを確認する。初回は既存上昇を止めていないfixtureでY期待が失敗し、新ケースだけ専用pause ownerを使いY=0の期待を維持した。
- 専用save `save/ui-round32-width-battle-v188`。実表示の全4種類、右端通常敵／右端ボス／左端プレイヤー、異なるownerの同時8表示で文字同士と表示中の全敵TextMeshに重なりなし。ポーズ・カスタム中の位置／alpha／論理frame保持、手動pause解除でカスタム停止を解除しないこと、取消・再利用、自然消去2周、保存hash不変を確認した。
- 独立sourceレビューのforceRenderingOff指摘を修正。最終ソース・640×360統一条件でUnity MCP全3,460/3,460成功（266.99秒）、console error 0／warning 66。180秒の呼出側期限後も同じ実行を回収し重複起動なし。対象8ファイルと製品保護6ファイルの前後SHA256一致。独立最終source／資料／10PNGレビューの今回範囲未解決0。
- フォントは実表示もJikiTourai。背景・文字列規則・scale・ダメージ／回復値・防御規則・効果時間・固定frame・保存形式・Unity参照は変更していない。7／回復7／Aura100／配置は検証入力のみ。

今回のFHD／4Kと回帰条件の結果であり、任意の巨大群・左右に空間がない場合の非重複保証ではない。物理pad／実OS通知／音声聴感／実保存障害は今回未検証。次の有益な観点は、既存の戦闘終了・報酬遷移直前の一時表示と操作復帰。未決の性能値を追加する候補ではない。
