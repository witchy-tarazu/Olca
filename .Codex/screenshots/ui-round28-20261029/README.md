## 実行した経路

通常DungeonBattleControllerを専用領域で起動し、敵カードの攻撃でHP100→93・HUD93を確認した。敵カード7ダメージ・毒0ダメージ／240frame・混乱240frame・回復5は隔離した検証用入力で、製品定義へ登録していない。攻撃・HP反映・フィードバック・カスタム開閉は既存コードを通している。状態付与／解除・回復値の投入はBattleSystem.RunLogicalFrameを使う制御検証で、既存製品カードがそれらを持つという主張ではない。

カスタム中の状態残量／論理frameは撮影をまたいで不変。終了して通常進行した後は毒・混乱が自然消失し、無期限ガードだけ残る。HP98の詳細を開いたまま回復上限100とガード解除を投入し、HUDと本文が追従。解除確定後の再表示に古い状態が残らない。最終の表示サイクル前後で専用save3ファイルのhash不変。

混乱の解除予約は停止中に確定させず、次の進行する論理frameで確定する既存契約。解除予約が残る同一停止frameに新付与を重ねるfixtureでは解除が優先するため、再付与の比較は解除を通常frameで確定させてから行った。表示だけで予約を確定させていない。

詳細入力は既存の手札表示遷移が終わりボタンがinteractableになった後に確認した。固定400msだけ待った初期の検証スクリプトは遷移中のクリックで詳細を開けず、待機条件を訂正して再確認した。製品の時間設定は変更していない。

実機pad、実OS休止通知、音声聴感、実保存障害、高解像度の時間保証、複数敵／ボス死亡時のHUD同期は今回の完了範囲に含めない。背景・JikiTourai・漢字だけの置換・LIFO・固定frame・保存とUnity参照を保持。最終全件とレビューはPlanning参照。
