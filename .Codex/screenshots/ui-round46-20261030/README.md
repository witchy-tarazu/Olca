前単位で敵側の遮蔽は解消したが、4:3の本文は約16.5px相当で上下余白が大きかった。今回は左半幅を維持しながら縦方向へ配置を広げ、読書用の文字と操作文字を大きくした。FHD/4Kと閉状態は従来配置へ戻す。

## 変更

- 本文/コスト/確定はfontSize×描画倍率換算で約23.61px相当へ。補助操作は約21.25px、Pad案内は約17.70px相当。JikiTouraiを維持し、文字の読みとひらがな等の扱いは変更しない。
- 本絵の右側の説明欄を380×270から460×650論理UI単位へ。左端を保ち、カード本絵280×280とアイコン100×100は等比のまま。手札は最大10枚・5列2段のまま、2段目との縦間隔を広げた。
- 上部操作/HPと、コスト/選択済み列/確定を上下へ配分。4:3では背景外周が左半幅720px内に収まり、カードと確定入力は約59pxで48px以上。
- 元背景PNGを編集せず、実行時Spriteの縦スライスで直線部だけを延長。角・HP枠と既存色を維持。カード絵やキャラを引き伸ばしていない。生成Spriteは所有者の破棄時に解放し、元Sprite/Textureは保持。
- 手札コスト数字の枠不足を実画像で発見し、100幅を維持したまま高さと下余白を確保。4:3ではボタンのBestFitによる縮小を解除し、標準比率では元の値・BestFit設定を復元。
- Padガイドはキーと操作を組にした明示的な4行へ。標準比率の元の2行案内とキー対応は変えない。
- 変身候補があるときは説明欄と重ならない高さを予約し、続きは既存スクロールで読む。今回の実表示確認は2候補の検証用定義まで。

ゲームのコスト・威力・発生/硬直・固定論理frame・開閉時間・報酬・保存形式は不変。戦場カメラとキャラ/敵の座標・尺度は変更しない。Unityのserialized参照、背景原画とフォント参照も保持する。

- [10枚・仮想パッド案内](ten-pad-4by3.png): 既存カタログのカード追加APIで隔離fixtureを10枚にしたもの。製品データへのカード/性能追加ではない。

- Unity EventSystem Raycast→pointer clickで選択、LIFO、空取消、非表示/復帰、pause/復帰を2周確認。カスタム中の論理frameを保持。確定後は倍率1・x−900、背景高さ1000・ゲージ高さ750へ復帰し、再表示も半幅内。

## 検証とレビュー

Unity 6000.3.26f1、Unity MCP EditMode最終全3,471件成功（237.23秒、失敗/skip0）。カスタムUI関連368件（新規回帰2件含む、22.99秒）、進行199件（72.87秒）も成功。

最終console→全件→consoleでerror0/compile error0。groundTruth警告66件（警告0とは報告しない）。MCP呼出しの180秒待機期限を超えたが、同一実行をtest_statusで回収し重複起動していない。native終了時のPipeline HTTP内Thread was being aborted 1件はスタックを保存・分類後clearし、製品側例外や最終全件後のerror0と区別した。最終ソースhashは検証用と公開用で一致。最終Editor/runner停止、実Screen/GameView640×360、専用TMPDIRと保存ガードも再確認済み。

独立コード/原寸視覚レビューで、キャッシュ保持、Padガイドのキー/動作分断を指摘され修正した。実画像でコスト数字のクリップと変身状態ラベルの左切れも発見し修正。今回の最終画像の具体的な美観指摘は0件。原寸レビューでは本文・数字・操作と5×2区分が読みやすくなり、敵側を隠さないことを確認した。これは全画面/全データの無欠陥保証ではない。
