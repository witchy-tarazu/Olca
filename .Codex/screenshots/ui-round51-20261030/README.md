# Round51: ショップと帰還結果の情報階層

ショップの商品名・価格が一行に混在し、帰還の数値・カード名が大きな空白へ散在していた表示を整理した。既存の水／鏡の青白い素材とJikiTouraiを使い、背景・キャラ素材・スケールは変更していない。

## 表示の変更

- ショップは見出しと所持通貨、商品群、取引案内、操作を分けた。商品名／説明と右揃えの価格・状態を独立させ、通常2商品では行の高さを、密な5商品では内側余白を確保した。削除など単行の商品は縦中央へ揃えた。4:3では基準面を等比で収め、操作を欠けさせない。
- 帰還は経験値／成長と変換トークンを分け、持ち帰りカードを見出し直下の左揃え行へまとめた。選択枚数に合わせて面と確定位置を詰め、長名3枚も個々の行を区別できるようにした。Choosingの8行ページング、Returnedの編成・再出撃、敗北／撤退でクリア報酬まとめを表示しない規則は保持する。
- 購入済みの表示で発見した「購入」のカナ変換漏れを、既存の表示辞書へ追加した。元のひらがな・英数字、カード名・説明の原データは保持する。

## 完了した素材参照の接続

新しい絵を重複制作せず、既存の専用miniアイコンを商品と帰還カードへ接続した。本絵の縮小・拡大代用ではない。

ショップは`state.Options`順の型付き定義とPurchased・通貨を明示して渡す。価格を表示文字列から解析せず、選択callbackのindexと一致させる。価格不足でも選択は可能、確定可否は従来のCore判断のまま。旧signature相当の呼出しは文字列のfallback表示を保持する。

帰還は`ReturnCardData.ValueHash`を定義キーとして既存の所有定義resolverへ渡し、一意に解決したカードのminiだけを借用する。同名だけで別定義を決めず、未解決なら番号表示を残す。SpriteをViewから破棄しない。未定義の価格・商品表・報酬・能力値、保存形式は追加していない。

## 実操作と保存

専用セーブで初戦報酬からショップ・回復・次戦を通った。商品選択取消で通貨10／デッキ6／獲得0を保持し、連続確定でも購入は一度だけ（通貨5／7枚／獲得1）。削除の仮選択取消は不変、連続確定後は通貨0／6枚／獲得履歴1。退出保存と回復の取消・一度だけの確定（HP80→87）、次戦の選択0・論理frame0・HP87も確認した。検証用の敵状態・ダメージ設定と実入力を区別し、製品性能を変更していない。

別の隔離マップでは初戦カード受取→ボス撃破→持ち帰り1枚→経験値反映→帰還を実Raycastで操作した。ディスクを読み、Awarded／Returned、経験値100・Lv2・所有カード1件・受領記録1件を確認。確認前に保存完了とは扱わず、既存の報酬／帰還確定の保存順を維持した。[実クリアの反映画面](live-awarded-fhd.png)と[帰還後](live-returned-fhd.png)はfixtureと別画像。

独立した原寸視覚レビューで、単行商品の重心、見出しとカード名の距離、長名カードの区切り、5商品長名行の上下余白を指摘され、各画像で再確認して解消した。独立コードレビューも行った。指摘0は今回の範囲に限り、ゲーム全体や美観の完成を意味しない。

## 残る範囲

次の有益な候補は、ショップ削除の選択モーダルと帰還後の所有カード一覧を同じ情報階層へ整えること。6商品以上の大量一覧の原寸QA、物理タッチ／パッド、OS IME、音の聴感は今回未確認。密度が高い行では追加した説明を省いて、従来の名称・状態・価格を保つ。未決の製品値や拒否済み攻撃本体素材は本成果に含めず、生成の再試行もしていない。
