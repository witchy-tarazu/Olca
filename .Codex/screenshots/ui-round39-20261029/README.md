# 通常探索のHP表示を既存ステータスバーへ接続（2026-10-29）

## 既存要件と原因

`Planning/ビジュアル・アート/UIデザイン仕様.md` の「ダンジョン探索画面UI」（486行以降）は、上部ステータスバーに`[HP] [アイテム数] [階層] [Menu]`を示している。同文書の更新commitは`5e42fcc9920399d11eed61446c2c9d5a4e82c068`であり、今回追加した要件ではない。全体仕様§16だけでは表示要件を断定できなかった前回の候補分類を、この探索UI節も照合して既存の未接続と判断した。

`DungeonHudView.Refresh`にはHP更新があるが、通常の`Assets/Scenes/DungeonScene.unity`の`hpText`は`8edfd44175699f028c20fad06757eb0e8d774483`で探索HUDを接続した時点から未割当だった。HP83になった通常探索の実PlayでもTextが存在せず、FHD／4Kで欠落を再現した。表示削除の退行や、HP表示を意図的に禁止した仕様変更は見つからなかった。開始・区切りのpullで追加仕様はない。

## 最小修正

- 未割当のHP欄だけを既存HUD内の左上へ一度生成し、既存`Refresh`の値更新とCanvasGroupの表示切替を使う。新しいHPゲージや画面、性能値は追加しない。
- Controllerが既存カスタムUIから使っているフォントを生成HP欄へ供給する。実PlayでJikiTouraiを確認。初案では探索枚数欄のLegacyRuntimeを継承したため、その案を完成扱いにせず修正した。
- 既存Sceneに明示されたTextとフォントは変更せず、生成HPだけを対象にする。HP文字はraycastを遮らず、背景・他の配置・既存素材を変更しない。
- 実Sceneを読む回帰1件を追加し、値更新・単一生成・同参照・既存UIフォント継承・既存割当の保持を確認する。このテストでの再開値入力と、下記の実ファイル再開は分けている。

## 実Play

専用保存とガードを使う隔離fixture（マグマ1の被害17・回復アイテム3の回復17・通常敵10・後続ボス22）だけを設定した。製品配置・製品数値に登録しない。

1. HP100→マグマで83、ポーズして`HP: 83 / 100`を確認。修正前は同じ位置／HPで表示なし。修正後はJikiTourai、Text1個、CanvasGroup alpha1。
2. 所持カード一覧を開閉してポーズへ戻ってもHP83・同じText1個を維持。
3. 明示再開後の実回復アイテム取得で100表示。停止中の検証用被害9で91表示へ更新。
4. 実ファイルの「続きから」でDepartureの位置0／HP100へ戻り、表示も100へ復帰。旧91表示は残らない。
5. 通常接敵後は探索HUDのalpha0となり、既存の戦闘／カスタムHP100だけが見える。
6. 検証用に通常敵を撃破し、既存のカード・通貨スキップを操作。通常探索へ戻るとalpha1・HP100・同じText1個に復帰した。

初回の報酬操作後に階層fixture専用の補助戻り値処理が失敗し、続行スクリプトにも初期化手順が含まれていたため、その途中結果を最終成功に数えていない。最終の独立fixtureで上記を通し直した。上端欠けを疑った画像も実画素で確認し、FHDの明るいHP文字はx38〜237・y35〜58に収まっていたため配置の追加変更はしなかった。
