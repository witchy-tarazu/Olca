# Round 45: カスタムの半画面内レスポンシブ配置

基準master `995f01ebcd0afc7d1abc99ee455394458efcc968`。開始時と検証前の通常pullで追加仕様更新なし。

## 実画面での問題と修正

固定960幅のカスタムに加え、HP/ゲージを含む背景の右端が1220へ張り出していた。4:3では敵名・HP・本体がカスタムの下に隠れていた。

`BattleView`で元背景の外周を測り、開いた状態では左半画面へ一体で等比配置する。4:3の倍率は720/1220≒.59016、FHD/4Kは960/1220≒.786885。狭い画面だけでなく16:9もHP枠込みで半幅へ収めるため、従来より少し小さくなる。広い画面でも原寸より拡大しない。

内部のカード列・本絵・miniアイコンの比率と各文字のfontSizeは変更しない。左端・縦中央基準を保ち、キャラ/敵/戦場カメラのscale・anchor・位置を変更しない。画面上下には余白が増えるが、戦場を覆わず一体のパネルとして構成する。

閉状態は元の倍率1・x−900を保持。開閉の補間位置とovershootへ同じ倍率を適用し、リサイズ時もauthoring座標から計算する。既存の開閉時間・停止・固定論理frame・コスト・報酬・保存形式・Unity serialized参照は不変。

根拠: `Planning/ビジュアル・アート/カスタム画面仕様.md`のレスポンシブ対応（左端追従、部品の配置、カード/確定入力48px以上）と既存の左寄せ/パネル+ゲージ半画面というユーザー方向。新しい探索デッキ規則や性能値は追加していない。

## 操作と検証

- 実EventSystem Raycast→pointer click経路で2周。Sword/Bomb選択、選択領域からLIFO、空取消、非表示/復帰で選択保持、手動pause/復帰を確認。各カスタム操作中の論理frameは0のまま。
- 4:3で背景右端720px/画面半幅720px、カード最小辺59.016px、確定ボタン最小辺59.016px。48px以上を維持。
- 確定後は倍率1・位置−900へ戻り、既存sessionの再表示経路でも半幅へ収まる。再表示fixtureのゲージだけ既存APIで満タンにしており、製品の速度や時間は変更していない。
- 最初の閉鎖確認fixtureはpause復帰と同一入力境界のconfirmを送ったため、既存の復帰入力遮断で受理されず期待した閉状態にならなかった。通常の明示入力まで300ms待って入力遮断解除を確認した後、同じ未変更ソースで正常な閉/再表示を検証。製品側の入力ガードや期待値は緩和していない。
- 境界回帰3ケースで1440/1920/2560、開状態・途中位置・overshoot中のリサイズと閉HUD原寸を確認。独立レビューで幅復元後assert不足を指摘され修正した。
