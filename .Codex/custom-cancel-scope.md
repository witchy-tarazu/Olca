# カスタム画面の末尾取消と表示同期

根拠: Planning/ゲーム全体仕様.md §5（最後に選択したカードから取り消す）、§3（カードを外してから未確定変身を取り消す）、§6（加工Undoは履歴を逆順に戻す）。

通常ESCは従来、先頭から全カードの解除を試み、Coreが末尾以外を拒否しても全ハイライトを消していた。末尾1枚の解除に統一し、成功後のCore選択からハイライト・コストを更新する。時刻付き入力の取消エッジを既存キューで一度だけ処理する。既存のSpace→Enter→取消の判定順を維持する。加工モード中のESCは引き続き加工モードへ委譲する。

完了条件: 実View/戦闘セッションで末尾1枚・残るハイライト・連続選択割引を照合。30/60/120fpsと追いつき、戦闘開始保存復帰、同一更新のESC押下解放、ポーズ・確定中の遮断、明示加工Undoによる素材・手札順・コスト復元を確認する。保存schema/sequence/MapHash/デッキ順を変えない。全Unity MCP EditMode回帰も実施する。

範囲: 通常のカード選択取消。手札への返却位置は既存Core（手札末尾）を維持し、新しい並べ替え規則は設けない。通常取消ではゲージを消費せず、画面を閉じる時の既存処理で消費する。加工履歴や変身仮選択も通常カード取消では消さない。

残件: 変身仮選択の追加取消自体は既存CoreのTryCancelPendingで実装済みだが、空選択時ESCからの接続と変身選択の実UIは今回の範囲外。変身ごとのカード変化対象・変化先、手札上限増分などの実定義はなく、変身由来の加工巻戻しと追加ドロー復元は未実装。独立した確定範囲が尽きたとは扱わない。基本攻撃定義不足など既報の残件も継続。

保存は既存の戦闘開始チェックポイントを使い、カスタム画面途中の新規保存形式は追加しない。描画VM同期・新しい実機確認・buildは実施しない。

追記: 空選択時ESCから既存TryCancelPendingへの接続は後続の .Codex/pending-transformation-cancel-scope.md で対応。上記は2f9c87f時点の範囲記録。

2026-10-21追記: 外部定義の手札加算値、変身選択の実UI、即時追加ドローと取消時の同順復元を接続。追加分を素材にした加工だけを連鎖取消し、無関係な加工は保持する。確定後の上限低下は超過手札を保持。保存は従来のBattleStart再開で二重補充を防ぐ。詳細・仮判断・最新検証はPlanning/暫定実装一覧.mdの「変身の手札上限・追加ドローと取消復元」を参照。変身によるカード変換そのものと、その変換に由来する加工の取消は引き続き残件。

2026-10-21追記: 外部指定のカードID→置換テンプレートを変身選択へ接続。未確定の変換とそれに依存する加工だけを連鎖取消し、確定後の変化は終了後も保持する。追加ドロー復元と共用し、継続中は新規ドローだけ変換。以前の未実装記載は当時の範囲で、現在の判断・検証はPlanning/暫定実装一覧.md末尾を参照。製品変身/解放データ・変身専用攻撃は未追加。
