# 初回敗北・撤退の外界復帰

対象は既存の初回出撃 capsule に Template と Runtime がある場合。初回の敗北・撤退は既存仕様の外界死亡復帰と同じ全回復・状態解除・登録復帰地点への移動・ゲージ全快・手札再装填を行う。費用・経験値・持帰り報酬は適用しない。

一時Outside Sessionで出撃時Runtimeと専用RNGを復元し、既存RecoverOutsideを使って候補を作る。Rootの生きたactor/cards/Coreは保存前に変更しない。出撃元player/runtime key・復帰地点・候補player/runtimeをOutsideRecoveryDataへ凍結し、既存Stageの同一保存にFlow/receipt/外界保存を含める。成功後の既存復元経路が適用する。再試行・再起動は凍結結果を用い、二重シャッフル・二重支払を防ぐ。

旧Flow/receiptのnullを後から埋めない。旧出撃にRuntimeまたはTemplateがなければ従来経路を維持する。未知地形定義やカード定義は保存前に拒否し、S10の製品デッキ登録を仮決めしない。現在登録済み試用地形だけが対象。

未確定の新マップ到着処理、製品地形、S10/S13、外界戦闘や攻撃は追加しない。

## 検証

関連326件（Management102 / Session88 / Return136）、最終全4193件、同Editor UI反復408件すべて成功。実640×360・両RT・専用TMPDIR/saveguardで実行し、最終4ソースhashはコードレビューと一致した。初回コンパイルでは既存internal/private APIを別assemblyから参照したテスト/検証コードを修正し、製品APIの公開範囲や期待値は緩和していない。履歴は保存した。

その後、移動と選択変更→host Close/Bootstrap Single→同じactor/cards/Coreと現位置を保持、保存再適用なしを確認。時計停止から再開と同時に方向を保持する検証手順は既存neutral gateに遮断されたため、再開後に中立入力を通してから歩行する手順へ修正した。製品の入力保護は変更していない。前回終了済み出撃が保存に残る点も2周目ヘルパーへ反映した。

FHD/4K/4:3原寸を確認し、既存背景・フォント・本体と足元・HUDの新退行なし。独立コード/視覚レビューを実施。物理入力・聴感・全HotReload、未実装NPC/敵や世界要素の復元、S10/S13、旧Wind移行、歴史的UGUI/Pipeline/CLI/UnityAIと登録外Sprite基準群は別の制限として保持する。

## 仕様と範囲

根拠はゲーム全体仕様の初回敗北/任意撤退（317-318行付近）、外界死亡復帰・状態解除・ゲージ/手札復元、および冒頭の更新済み復帰地点規則。通常マップ移動による更新済み地点も含む仕様だが、現在実装済みの地点resolverは既存の試用地形/回復点のみ。本変更で製品マップや通常マップ遷移を追加した扱いにはしない。不明な地形/カード定義は既存保存を残して停止する。旧null Runtimeから失われた位置/手札を作らず、旧Flow/receiptのnullへ後付けしない。

保存失敗した撤退はまだ確定していないため、再起動後はcheckpointからの攻略継続を保ち、再操作時に同じ出撃capsule/RNGから復帰候補を作る。終端HP0が保存済みの敗北は再起動で判別して復帰保存を再試行する。成功済みFlow/receiptは凍結結果を再利用し、再シャッフルしない。
