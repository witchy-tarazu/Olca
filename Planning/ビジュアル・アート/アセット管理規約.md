# アセット管理規約 - Olca

## 概要

本ドキュメントは、Olcaプロジェクトにおけるアート関連アセットのファイル命名規則、ディレクトリ構造、管理方法を定めます。
統一された規約により、アセットの検索性・保守性・チーム作業効率が向上します。

## ファイル命名規則

### 基本ルール

```yaml
形式: [カテゴリ]_[名前]_[バリエーション]_[サイズ].[拡張子]
小文字とアンダースコア: すべて小文字、単語区切りは_
英数字のみ: 日本語は使用しない
簡潔に: 冗長な名前は避ける
```

### カテゴリ別命名規則

#### スプライト（キャラクター）

```
形式: [キャラ名]_[アニメーション]_[方向]_spritesheet.png

例:
player_idle_spritesheet.png
player_walk_down_spritesheet.png
slime_attack_spritesheet.png
boss_dragon_idle_spritesheet.png
```

#### スプライト（アイテム・オブジェクト）

```
形式: [アイテム名]_[サイズ].png

例:
potion_red_32x32.png
sword_steel_64x64.png
chest_32x32.png
door_32x64.png
```

#### タイルセット

```
形式: [場所]_tileset.png または [場所]_autotile.png

例:
dungeon_tileset.png
dungeon_autotile.png
forest_tileset.png
town_tileset.png
```

#### ADV立ち絵

```
形式: [キャラ名]_[パーツ]_[バリエーション].png

例:
alice_base.png
alice_face_normal.png
alice_face_smile.png
alice_face_angry.png
alice_pose_normal.png
alice_pose_armcross.png
```

#### ADVスチル・背景

```
形式: [種類]_[番号]_[説明].png または [場所].jpg

スチル:
event_01_meeting.png
event_02_battle.png
ending_01_happy.png

背景:
room_home.jpg
town_square.jpg
dungeon_entrance.jpg
```

#### UI要素

```
形式: [UI種類]_[名前]_[状態].png

例:
button_primary_normal.png
button_primary_hover.png
button_primary_pressed.png
icon_hp_32x32.png
panel_background.png
gauge_hp_fill.png
```

#### エフェクト

```
形式: [エフェクト種類]_[サイズ]_spritesheet.png

例:
slash_64x64_spritesheet.png
fire_256x256_spritesheet.png
hit_32x32_spritesheet.png
heal_128x128_spritesheet.png
particle_glow_128x128.png
```

#### アニメーションクリップ

```
形式: [キャラ名]_[アニメーション名].anim

例:
Player_Idle.anim
Player_Walk.anim
Player_Attack.anim
Slime_Idle.anim
```

#### マテリアル

```
形式: [用途]Material.mat または [名前].mat

例:
CharacterMaterial.mat
UIMaterial.mat
Additive.mat
AlphaBlend.mat
```

#### シェーダー

```
形式: [機能名].shader

例:
AdditiveSprite.shader
OutlineSprite.shader
DissolveEffect.shader
```

#### スプライトアトラス

```
形式: [カテゴリ]Atlas.spriteatlas

例:
PlayerAtlas.spriteatlas
EnemiesAtlas.spriteatlas
UIAtlas.spriteatlas
EffectsAtlas.spriteatlas
```

## バージョン管理

### ファイルバージョニング

制作途中や修正版を管理する場合:

```
形式: [ファイル名]_v[バージョン番号].拡張子

例:
player_idle_v01.png
player_idle_v02.png
player_idle_v03.png（最新版）
```

### 旧バージョンの保管

```
ディレクトリ構成:
Art/Sprites/Characters/Player/
├── player_idle_spritesheet.png（最新版）
├── player_walk_spritesheet.png
└── _Archive/                     # 旧バージョン保管
    ├── player_idle_v01.png
    ├── player_idle_v02.png
    └── ...
```

ルール:
- 最新版のみ直下に配置
- 旧バージョンは `_Archive/` フォルダに移動
- `_Archive/` はビルドから除外（.asmdef設定）

## メタデータ管理

### Unityインポート設定の統一

各アセットタイプごとに標準設定を定義。

#### ドット絵スプライト

```yaml
Texture Type: Sprite (2D and UI)
Sprite Mode: Multiple
Pixels Per Unit: 16（または32、プロジェクト統一）
Filter Mode: Point (no filter)
Compression: None
Max Size: 2048
Format: RGBA 32 bit
```

#### 通常イラスト（立ち絵・スチル）

```yaml
Texture Type: Sprite (2D and UI)
Sprite Mode: Single
Filter Mode: Bilinear
Compression: ASTC 6x6 block
Max Size: 2048
Format: RGBA Compressed
sRGB: チェックあり
Alpha Is Transparency: チェックあり
```

#### UI要素

```yaml
Texture Type: Sprite (2D and UI)
Sprite Mode: Single
Filter Mode: Bilinear
Compression: ASTC 6x6 block
Max Size: 1024
Format: RGBA Compressed
```

#### エフェクト

```yaml
Texture Type: Sprite (2D and UI)
Sprite Mode: Multiple
Filter Mode: Bilinear
Compression: None（加算合成で色が変わるため）
Max Size: 2048
Format: RGBA 32 bit
Alpha Is Transparency: チェックあり
```

### Import Settingsプリセット

Unity 2020以降の場合、Preset機能を活用:

```
Assets/Art/ImportPresets/
├── DotSpritePreset.preset
├── IllustSpritePreset.preset
├── UIPreset.preset
└── EffectPreset.preset
```

使用方法:
1. テクスチャを選択
2. Inspector上部の「Preset」ボタンをクリック
3. 該当するプリセットを選択

## アセットラベル（Tags）

### ラベルの活用

Unityのラベル機能でアセットを分類:

```yaml
カテゴリ別:
  - Character
  - Enemy
  - NPC
  - Item
  - UI
  - Effect
  - Background

品質別:
  - Final（完成品）
  - WIP（作業中）
  - Placeholder（仮素材）

用途別:
  - Battle
  - Dungeon
  - Menu
  - ADV
```

### ラベルの設定方法

1. アセットを選択
2. Inspector下部の「Labels」をクリック
3. ラベルを追加

検索例:
```
Project検索欄に「l:Character l:Final」と入力
→ 完成したキャラクターアセットのみ表示
```

## ソースファイル管理

### ソースファイル（.psd, .aseprite等）の扱い

```yaml
原則: Unityプロジェクトに含めない
理由:
  - ファイルサイズ肥大化
  - ビルドに不要
  - バージョン管理の負荷

推奨: 別フォルダで管理
```

### ディレクトリ構成（Unity外）

```
ProjectRoot/
├── UnityProject/（Unityプロジェクト）
│   └── Assets/
│       └── Art/（出力したPNG等）
│
└── SourceFiles/（ソースファイル保管）
    ├── Characters/
    │   ├── player.aseprite
    │   └── slime.aseprite
    ├── ADV/
    │   ├── alice_portrait.psd
    │   └── event_01.psd
    ├── UI/
    │   └── button.psd
    └── Effects/
        └── fire_effect.psd
```

### 例外: Unityに含める場合

以下の場合のみUnityプロジェクト内に配置:

```
Assets/Art/SourceFiles/（.gitignoreで除外）
または
Assets/Art/Templates/（テンプレートとして参照用）
```

## アセット管理ツール

### 推奨ツール

#### 1. Addressable Asset System

大規模プロジェクトでは使用を検討:

```yaml
メリット:
  - 動的なアセットロード
  - メモリ管理の最適化
  - アセットバンドルの簡易化

使用例:
  - ADVの立ち絵・背景
  - 大量のエフェクト
  - シーン別アセット
```

#### 2. Sprite Atlas

スプライトの自動アトラス化:

```
Assets/Art/Atlases/
├── PlayerAtlas.spriteatlas
│   - 含まれるフォルダ: Art/Sprites/Characters/Player/
├── EnemiesAtlas.spriteatlas
│   - 含まれるフォルダ: Art/Sprites/Characters/Enemies/
└── UIAtlas.spriteatlas
    - 含まれるフォルダ: Art/UI/
```

効果:
- Draw Call削減
- メモリ効率向上

#### 3. AssetGraph（オプション）

アセットの自動インポート・処理パイプライン構築:

```yaml
使用例:
  - スプライトシートの自動分割
  - テクスチャ圧縮の自動適用
  - 命名規則チェック
```

## アセット納品チェックリスト

新規アセット追加時、以下を確認:

### ファイル名
- [ ] 命名規則に従っているか
- [ ] 小文字とアンダースコアのみか
- [ ] 日本語が含まれていないか

### ディレクトリ配置
- [ ] 適切なフォルダに配置されているか
- [ ] 重複ファイルがないか

### Unityインポート設定
- [ ] Texture Typeが正しく設定されているか
- [ ] Filter Modeが適切か（ドット絵はPoint、イラストはBilinear）
- [ ] 圧縮設定が適切か
- [ ] Max Sizeが適切か

### ファイルサイズ
- [ ] 不要に大きくないか（推奨: 2MB以下/ファイル）
- [ ] 解像度が過剰でないか

### 透過設定
- [ ] 透過が必要な画像はPNGか
- [ ] Alpha Is Transparencyがチェックされているか

### アトラス化
- [ ] 該当するSprite Atlasに追加されているか

### メタデータ
- [ ] 適切なラベルが設定されているか
- [ ] ステータスラベル（Final/WIP）が設定されているか

## トラブルシューティング

### よくある問題と解決策

#### 1. スプライトがぼやける
```
原因: Filter ModeがBilinearになっている
解決: Filter ModeをPoint (no filter)に変更
```

#### 2. スプライトの色が変わる
```
原因: sRGBがオフになっている、または圧縮形式が不適切
解決: sRGBをチェック、圧縮をNoneまたはRGBA 32 bitに
```

#### 3. アトラスに含まれない
```
原因: フォルダ指定が間違っている、またはPlatform設定
解決: Sprite Atlas設定を確認、Include in Buildをチェック
```

#### 4. ファイルが見つからない
```
原因: 命名規則が統一されていない、配置場所が間違っている
解決: 本ドキュメントの命名規則・ディレクトリ構造を再確認
```
