# 再挑戦の外界Runtime退避と再起動復元（2026-11-10）

## 実装した範囲

全体仕様§2の「再挑戦では入場前の探索状態を保存して戻す」に従い、新しいRuntime付き再挑戦のクリア・敗北・撤退へ、現在実装済みの外界Core／カメラ方針／ゲージ／カード状態を接続した。Stage140のHP・状態・成長差の固定計画と同じ帰還保存で確定する。ダンジョンの座標・敵・デッキ・時計を外界へ転用していない。

|対象|保存・復元する状態|
|---|---|
|Core|論理Frame、連続座標、向き、高さ・縦速度、接地先、移動/Idle frame、固定小数点余り|
|移動状態|dash残時間・回数・cooldown、dash jump、壁滑り/壁蹴りの論理時計と向き、残像4個以内|
|表示方針|追従/固定カメラの論理中心。Root所有Unity Camera/Listener等は保存物にしない|
|ゲージ|最大値・回復速度・整数単位の残量。復元で満量にしない|
|Cards|未登録null、または既知20個体の定義/加工履歴、順序、手札、drawn/returned履歴、選択、revision、専用乱数状態|

UI入力キュー、物理キー保持、入力配送用の時刻は復元しない。ジャンプ/dash入力latchは解放し、既存の復帰neutral契約を維持する。ゲームのCore.Frameは保存値から60Hzで進む。現在未実装の外界敵registry・攻撃state等を仮生成して「完全な世界」を保存したことにはしない。

## 保存と適用の境界

`OutsideDepartureVitals.Runtime`へ表示を閉じた出撃境界で捕捉し、Flow/receiptへ固定する。`OutsideRuntimeSave`はActor snapshotと同じ攻略IDで帰還保存に含め、成功後だけRoot Sessionへ適用する。Flow／receipt／出撃snapshotのキーと最新Actor/Runtimeの対応を検証する。失敗では旧保存・旧Sessionを保持し、同じ計画を再試行する。

Actor、Core、初期地形設定、カメラ、Cardsの全候補を検証してから適用する。Core objectは維持し、warm Cardsは保存内容が同一なら同じ個体群を維持する。同ID・別内容の再適用は拒否し、通常の再表示/host再入では既に適用済みの境界へ巻き戻さない。snapshotは通常の深いコピーで、per-frameの進行参照のたびにJSON変換を繰り返さない。

地形・試走profileと物理値は定義hashで照合し、異なる定義を推測で読み替えない。版、座標、速度、時計、接地、壁接触、dashの矛盾、残像、カード参照、選択、乱数を検証する。Cardsの復元はShuffle/Drawを呼ばず、既存の登録定義と`SeededBattleRandom`の状態を再利用する。未知の乱数providerは捕捉時に拒否する。

回復ポイント/死亡復帰では新Actor snapshotを保存すると同時に古いRuntime保存を解除し、既存の回復・再装填・ゲージ全回復へ切り替える。warmの適用済みIDも新Actorと照合するため、以前のRuntimeを戻せない。帰還時のアイテムCD reset等の例外は、未実装のCDをこのsnapshotに含めて捏造しない。

## 互換と未完

新欄はoptionalで、旧nullのFlow/receipt/出撃を後から自動移行しない。旧fingerprintには新markerを追加せず、checkpoint schema・カード性能/定義hash・所持/費用/報酬・既存セーブを維持する。初回帰還・旧nullのcold全Runtime移行は今回対象外で、Stage139/140のHP経路を保つ。初回敗北/撤退の外界死亡復帰、S13の初回持込み、Battle.End前3状態捕捉も未完のまま。

現在の通常製品導線では探索Cardsは未登録nullで、S10の装備登録元を仮決めしていない。非nullの実経路試験では、隔離した既存スターター20枚を明示的に登録した。登録/入手を製品実装したという意味ではない。製品マップ・能力解放は既存の仮設定を維持し、新しい地形や敵配置を決定していない。アイテム実使用/回復量/CD定義の残件も別である。
