# 戦闘共通仮効果音（2026-10-27）

## 対象とイベント

基準master `2a37205e58899133762c9c6c8fe295d487fdbf8d`。既存 `PlayerCharacter` / `Enemy.OnCombatFeedback` の個別受理通知を唯一の発音入口とする。

|通知|共通仮音|長さ|
|---|---|---|
|Damage|damage（低い短い合成打音）|96ms|
|Guard / BarrierDamage / Immune|defense（短い高めの防御音）|72ms|
|Healing|healing（柔らかい短い二成分音）|128ms|

HPフレーム集計/OnHpChanged/OnPlayerAttackを重複購読しない。新しい攻撃開始・空振り・製品別発音契機は追加しない。0ダメージ/0回復など通知を出さない条件はCoreに従う。同一戦闘の再Bindは無操作、召喚はHashSetで一度だけ追加、交換/解除/破棄で旧購読を外す。Coreの判定/固定論理時計/時間定義/保存形式を変更しない。

`CombatFeedbackSubscription` と `CombatFeedbackAudio` はUnity音声アダプター側に置く。購読はCore型のみを参照し、Unity層からApplication層へ逆参照しない。

## 音素材と上限

外部素材/生成サービス/契約/課金なし。`Tools/Audio/create_placeholder_battle_sounds.py` を `python3 Tools/Audio/create_placeholder_battle_sounds.py` で実行し、`Assets/Resources/OlcaBattleSounds/{damage,defense,healing}.wav` を再現できる。スクリプトはこの3つの仮WAVを再生成するため、正式素材へ置換後は用途を確認する。

48kHz/16bit/mono PCM。固定seedの合成ノイズと正弦波にsin²窓、窓内DC除去、ピーク0.0799866（約−21.94dBFS）。両端0、隣接端点もゼロ付近。DC平均絶対値は最大約2.74e−7。Python波形解析とFFprobeのPCM形式/長さ/レート/チャンネルが一致する。UI仮音とは周波数/ノイズ/長さを区別したが、聴感を合格確認した意味ではない。

戦闘用は最大4つの非ループAudioSource。空きがなければ新しい音だけを抑制し、通知・判定を変更しない。戦闘音だけのフルゲイン振幅上限は4×0.0799866=約0.319946（クリップ振幅1未満）。BGM/UI等を含む最終ミックス全体の保証とは分ける。

## 再生と寿命

既存 `GameplayAudioRouter` のEffectsへ登録し、全体×効果音設定とユーザーポーズを共用。UI/BGM/Voiceとは別Sourceなので戦闘音のStopでUI音を止めない。停止中の新しい通知はキューへ積まず抑止し、再開でまとめて鳴らさない。再生中の音のpause/resumeは既存Routerに従う。

Controllerの通常戦闘開始/再有効でBindし、無効化・戦闘終了・撤退・チェックポイント交換・既存battleSession.Detachの各経路で解除/Stop。Sourceは最大4つを次戦でも再利用し、Controller破棄ではRouterから登録解除して所有Sourceだけを破棄する。共有AudioClipは借用し破棄しない。

## 検証

- Unity6000.3.26f1 / Linux。console → 全EditMode **3,190/3,190成功（226.27秒）** → console。関連8件成功。最終console error0・コンパイル失敗なし。
- PCM/共有対応、個別通知の一度購読、召喚、旧戦闘解除、Controller無効ガード、Router登録解除を回帰検証。初回の逆層参照コンパイル失敗を購読クラス配置で修正した。EditModeでOnDisableが自動実行されると仮定したテスト1件も、ライフサイクルを明示呼出する形へ修正した。期待件数を緩めていない。
- 独立レビューで「無効化中のControllerへの外部開始通知が再Bindできる」指摘を修正。開始/再有効入口の `BindBattleFeedback` が `isActiveAndEnabled` を確認する。再レビューの今回範囲の未解決具体指摘0。
- 専用 `save/combat-audio-proof-v96` へ起動前保存先注入・Controller起動後ガードを確認。通常Controller/ボス戦のソード選択→確定→使用ボタンで、Damage通知1回にSource再生1つ（`Damage:1`）を記録。
- 検証用の既存モデル操作で被弾/回復/ガード/バリアを与え、4音の内訳damage/defense/defense/healing、5音目抑止、同一Bind反復の非重複、全体×効果音gain0.1とmute、新規pause通知抑止と解除後の遅延再生なしを確認。実際のComponent.enabled切替で停止/再Bind、召喚通知・死亡、有限音の自然終了も確認。
- 通常Controllerのチェックポイント復帰で旧敵通知から発音せず新敵通知だけ発音。通常撤退でStop/Detach。Disposeで戦闘Sourceが消え、Routerは既存BGM/Effects/Voiceの3登録へ戻り、UI音を止めず共有Clipも破棄しないことをPlay確認。
- 音量/判定時間/本体画像/背景/JikiTourai/表示配置/保存形式に新しい製品値を追加していない。今回は画像変更がなく、追加FHD/4K表示検証対象はない。
- 最終640×360、Play停止、Controller非アクティブ、保存ガード正常。全件成功後の製品C#は不変。nosoundの再生API状態の結果であり、実音の聴感や最終ミックス波形を測った結果ではない。

## 残素材との境界

FMODは引き続き `nosound output`。スピーカー/ヘッドホンの聴感・実機出力品質は未確認。音声デバイスやOS設定は変更しない。BGM/声/専用製品音はこの3音と別の残素材。[未決仕様引継ぎ](未決仕様引継ぎ.md)の製品値/拒否本体画像/未決仕様を音素材完成へ混ぜない。
