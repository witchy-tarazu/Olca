## 1. プロジェクト概要

### ゲーム概要
**Olca（オルカ）** は、「ローグライク×アクション×デッキ構築」を組み合わせたカードアクションRPGです。

### コアメカニクス
1. **ダンジョン探索**: 自動スクロールのアクション要素（ジャンプ・ダッシュ）
2. **バトルシステム**: リアルタイム戦闘とカスタム画面の高速サイクル
3. **デッキ構築**: 戦闘中にカードを獲得してデッキを強化

### ビジュアルコンセプト
- **ドット絵**: キャラクター・ダンジョン・バトル画面
- **フラットUI**: 全UIコンポーネント
- **通常イラスト**: ADVパート・立ち絵

### アーキテクチャ原則
- **ロジックと表示の完全分離**: Core層（Unity非依存）+ Presentation層
- **Unity依存の最小化**: インターフェースを通じた抽象化
- **テスト可能性**: Core層は100%ユニットテスト可能

```csharp
public class CustomGaugeSystem
{
    private float currentGauge; // 0.0 ~ 1.0
    private float gaugeSpeed;

    public float CurrentGauge => currentGauge;
    public bool IsFull => currentGauge >= 1.0f;

    public void Update(float deltaTime)
    {
        if (!IsFull)
        {
            currentGauge += gaugeSpeed * deltaTime;
            if (currentGauge >= 1.0f)
            {
                currentGauge = 1.0f;
                OnGaugeFull?.Invoke();
            }
        }
    }

    public void Reset()
    {
        currentGauge = 0f;
    }

    public event Action OnGaugeFull;
}
```

#### 1.4 カスタム画面システム（Core/Logic/Battle）

##### CustomScreenSystem.cs
```csharp
public class CustomScreenSystem
{
    private Deck deck;
    private List<Card> currentHand; // 現在の手札
    private List<Card> selectedCards; // 選択中のカード
    private int maxHandSize = 5;
    private int maxCost = 10;

    public List<Card> CurrentHand => currentHand;
    public int RemainingCost => maxCost - selectedCards.Sum(c => c.Cost);

    // カスタム画面を開く
    public void Open(IRandomProvider random)
    {
        // 手札が上限になるまでドロー
        int drawCount = maxHandSize - currentHand.Count;
        var drawnCards = deck.DrawCards(drawCount, random);
        currentHand.AddRange(drawnCards);

        OnScreenOpened?.Invoke(currentHand);
    }

    // カードを選択
    public bool TrySelectCard(Card card)
    {
        // コスト制限チェック
        if (RemainingCost < card.Cost) return false;

        // 同名カード制限チェック
        if (selectedCards.Any(c => c.Name == card.Name)) return false;

        selectedCards.Add(card);
        return true;
    }

    // 選択完了（カスタム画面を閉じる）
    public void Confirm()
    {
        // 未選択カードを破棄
        currentHand.Clear();
        OnScreenClosed?.Invoke(selectedCards);
    }

    public event Action<List<Card>> OnScreenOpened;
    public event Action<List<Card>> OnScreenClosed;
}
```

public class ConfigurableInputProvider : IInputProvider
{
    private InputConfigSystem config;

    public ConfigurableInputProvider(InputConfigSystem config)
    {
        this.config = config;
    }

    public float Horizontal
    {
        get
        {
            float h = 0f;
            if (Input.GetKey(config.GetKeyBinding(InputAction.MoveLeft))) h -= 1f;
            if (Input.GetKey(config.GetKeyBinding(InputAction.MoveRight))) h += 1f;
            return h;
        }
    }

    public bool JumpButtonDown => Input.GetKeyDown(config.GetKeyBinding(InputAction.Jump));

## 6. リスク管理

### 技術的リスク

#### リスク1: Unity非依存アーキテクチャの難易度
**影響度**: 高
**対策**:
- フェーズ0で小規模なプロトタイプで検証
- インターフェース設計を慎重に行う
- 早期にテストを書いて動作確認

#### リスク2: カード効果の実装量が膨大
**影響度**: 中
**対策**:
- 基本効果テンプレートを作成（射撃、近接、範囲等）
- Strategyパターンで拡張性を確保
- 優先度をつけて段階的に実装（M4で調整）

#### リスク3: パフォーマンス問題
**影響度**: 中
**対策**:
- 早期にプロファイリング実施
- オブジェクトプール、Sprite Atlas化を徹底
- GC Allocを最小限に

### スケジュールリスク

#### リスク4: ビジュアルアセット制作の遅延
**影響度**: 高
**対策**:
- プレースホルダーで先行実装
- アセット制作をフェーズ3に集中
- 外部リソース（有料アセット）の活用検討

#### リスク5: スコープクリープ（機能追加の膨張）
**影響度**: 高
**対策**:
- MVP（最小限の実装）を明確に定義
- 拡張機能は「将来的な拡張要素」として後回し
- フェーズ5で余裕があれば追加
